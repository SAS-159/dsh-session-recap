## 2. 为什么是「会话复盘卡」

社区市场现有 9714 个插件（2026-11-09），其中有专门的 `usage`（用量与计费）分类，已有余额显示、账单面板一类插件——说明需求真实存在，也说明必须差异化。

我们的差异：

- **不是仪表盘，是产物。** 同类插件多数停留在"显示余额/用量"，我们输出的是一张可复制、可下载、可发布的卡片（Markdown / 独立 HTML）。
- **口径诚实。** 会话总额没有逐次时间戳，无法判断峰谷，所以显示"低谷价–高峰价"的区间，而不是编一个精确数字。
- **零权限。** 纯前端，`capabilities: []`：不读文件、不联网、不碰密钥、不跑 shell。在"只收录、不背书"的市场里，这是最低的信任门槛。
- **自带传播。** 用户晒复盘卡时会带上 DSH 画面——正好是"作品推广"想要的素材。

一句话介绍（市场条目用）：

> 在输入框下方为当前会话生成复盘卡：轮次、工具调用、Token 四段构成、缓存命中率与峰谷价花费区间，可导出 Markdown 或独立 HTML。

## 3. 上架路线（四步，第 1 步需要你的账号）

### 第 1 步：推到 GitHub（零介入模式）

把 GitHub PAT（只勾 `repo`）保存为纯文本文件：

```
C:\Users\26831\.dsh\github-token.txt
```

之后**不需要任何操作**：排程任务每 12 小时会跑一次 `node scripts/auto-release.mjs`，
它会自动完成 建仓库 → 设 `dsh-plugin` topic → push → fork 目录仓库 → 写入收录文件 → 开 PR。
仓库创建未满 24 小时时它只推代码、不建 PR，等下一次排程自动补上（CI 硬性要求满 1 天）。

手动触发（可选）：

```bash
node scripts/auto-release.mjs --check   # 只读：报告会做什么
node scripts/auto-release.mjs           # 真正执行
```

token 不进 `.git/config`、不进 URL、不打印：push 用临时 `http.extraheader`，进程结束即失效。
不想再用时删掉该文件即可。

**替代方案**（不想放 token）：网页建一个空仓库 → `git remote add origin …` →
`node scripts/release.mjs`，它会 push 并打印预填好的 PR 链接。

硬性要求（来自官方贡献指南，CI 会查）：

- 仓库**创建满 1 天**（防"PR 前几分钟新建"）
- 带 `dsh-plugin` topic（自动模式下脚本会设）
- `package.json` 声明 `dsh.bundle`，根目录有 `cordis.patch.yml`（本仓库已满足）
- 图标是 GitHub 托管的位图：用 `assets/icon-180.png`（SVG 不被接受）

### 第 2 步：发布 npm（可选）

市场条目**不要求 npm**：收录列表里大量条目用 `github:owner/repo` 直接安装，本包没有构建步骤，git 安装即可用。要发 npm 只是为了让安装更快、可版本锁定：

```bash

```

打开 → **Propose changes** → **Create pull request**，就完成投稿。
一个文件就是全部投稿，合并后站点与 `dshmarket` 通常一天内自动收录。

## 4. 申请文案（可直接粘贴，按表单字段微调）

**标题**：会话复盘卡 —— 让每次 Agent 会话的花费可见、可分享

**一句话**：把一场会话变成一张复盘卡：轮次、工具、Token 构成、缓存命中率、峰谷价花费，一键导出可分享的 HTML / Markdown。

**正文**：

> 我做了一个 DSH 插件 `dsh-session-recap`（会话复盘卡）。
>
> **解决的问题**：Agent 会话跑起来之后，成本是黑箱。输入框下方能看到上下文压力，但看不到这场会话用了多少未缓存输入、缓存命中多少、按官网价大概花了多少钱。重度用户不敢放开用，轻度用户不知道值不值。
>
> **做法**：在 `conversation.composer.dock` 挂一个入口，读取本会话已有的 `tokenUsage` 与 `sessionStats` 投影和 Chat 快照，聚合成一张卡：轮次、步数、总耗时、工具调用次数与 Top 工具、输入侧三分（未缓存 / 缓存读 / 缓存写）、缓存命中率，并按 DeepSeek Flash 官网峰谷价给出花费区间。卡片可一键导出为自包含 HTML 或 Markdown。
>
> **差异化**：① 纯前端零权限——不读文件、不联网、不碰密钥、不跑 shell，市场的安全扫描分类为空；② 导出物本身就是传播素材，用户晒复盘时会带上 DSH 的画面；③ 成本口径直接对齐官网定价页，峰谷价差如实呈现为区间，不制造精确假象。
>
> **已完成**：插件已在本机 DSH 安装并挂载（`conversation.composer.dock` 第 3 位，与内置 activity / usage 并列）；format-1 市场索引已通过官方校验器；代码 MIT 开源。
>
> **希望得到的支持**：① 一定额度的 token 赠助，用于在真实会话上验证成本口径与导出质量；② 插件 API 稳定性方面的技术沟通（尤其是 Chat 快照与投影字段的兼容策略）；③ 若质量达标，希望在官方市场或官方渠道获得一次展示位。
>
> **后续计划**：会话对比（同一任务不同模型/提示词的成本差）、团队周报（多会话汇总）、预算阈值提醒。

**支持诉求（勾选类字段）**：Token 赠助 / 技术讨论 / 作品推广。

## 5. 演示脚本（90 秒，录屏或现场）

1. 打开一个已有若干轮、用过工具的真实会话（不要用空会话）。
2. 指向输入框下方，说明内置的 activity / usage 两枚胶囊，然后点第三枚「复盘卡」。
3. 卡片弹出：先读第一行四个数（轮次 / 步数 / 耗时 / 工具调用），再说"这些是刚才这场会话的真实数据，不是示例"。
4. 指 Token 条：缓存命中、未缓存输入、缓存写入、输出四段，"命中率越高越省钱，这里能直接看到"。
5. 指花费区间："按官网 Flash 峰谷价，这场在 $x–$y 之间，所以显示区间而不是一个精确数字"。
6. 点「复制 Markdown」，粘贴到任意编辑器；再点「下载 .html」，用浏览器打开，说明这是一张可以直接发的卡片。
7. 收尾："插件不联网、不存数据，卸载即干净。"

截图建议（需真机）：① 胶囊按钮在输入框下的位置（亮色）；② 卡片展开（亮色）；③ 导出的 HTML 卡片（暗色）。三张即可覆盖市场详情页。
